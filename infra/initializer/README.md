# TripSphere Initializer

Run initializer commands from this directory:

```bash
cd infra/initializer
uv sync
```

## Base data

Run the following commands in order to import base data into MongoDB and
PostgreSQL:

```bash
uv run -m initializer.pois --uri mongodb://root:fudanse@localhost:27017
uv run -m initializer.hotels --uri mongodb://root:fudanse@localhost:27017
uv run -m initializer.room_types --uri mongodb://root:fudanse@localhost:27017
uv run -m initializer.attractions --uri mongodb://root:fudanse@localhost:27017
uv run -m initializer.spus --uri mongodb://root:fudanse@localhost:27017
uv run -m initializer.inventories --dsn postgresql://postgres:fudanse@localhost:5432/inventory_db
```

## Review-summary seed data and indexes

[`scripts/seed_review_summary.py`](scripts/seed_review_summary.py) generates a
deterministic set of 5-10 synthetic Chinese reviews for every hotel in
`hotel_db.hotels`. It writes the reviews to `review_db.reviews`, builds the
minimal pinned indexes in Qdrant and Neo4j, and verifies each hotel across all
three stores before recording it as `index_verified`.

The script is intended for development, testing, and dataset construction. It
does not scrape or copy reviews from external sources.

### Prerequisites

The following endpoints must be reachable from the host running the script:

- MongoDB containing `hotel_db.hotels`
- An OpenAI-compatible embedding endpoint returning 3072-dimensional vectors
- Qdrant
- Neo4j HTTP API

When local services must bypass a host proxy, include them in `NO_PROXY`, for
example:

```bash
export NO_PROXY=localhost,127.0.0.1
```

### Configuration

| Environment variable | Default | Purpose |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://root:fudanse@localhost:27017/?authSource=admin` | MongoDB connection URI |
| `OPENAI_BASE_URL` | `http://localhost:28080/v1` | OpenAI-compatible API base URL |
| `OPENAI_API_KEY` | `api-key` | Embedding API key |
| `EMBEDDING_MODEL` | `text-embedding-3-large` | Embedding model; output must contain 3072 dimensions |
| `QDRANT_URL` | `http://localhost:6333` | Qdrant HTTP endpoint |
| `NEO4J_HTTP_URL` | `http://localhost:7474` | Neo4j HTTP endpoint |
| `NEO4J_USERNAME` | `neo4j` | Neo4j username |
| `NEO4J_PASSWORD` | `fudanse@fudan.edu.cn` | Neo4j password |

Override credentials and endpoints for any environment that does not use the
local development defaults.

### Preview

Without `--apply`, the command only reads hotels and prints the planned counts
and sample reviews:

```bash
uv run scripts/seed_review_summary.py
```

Preview a small range:

```bash
uv run scripts/seed_review_summary.py --offset 0 --limit 5
```

### Write a small test batch

Start with a small batch and inspect its output:

```bash
uv run scripts/seed_review_summary.py --apply --limit 5
```

Each successful hotel prints `status: index_verified`. The command exits with a
non-zero status if any selected hotel ultimately fails.

### Write all hotels

```bash
uv run scripts/seed_review_summary.py --apply
```

The default manifest is written to the ignored file
`data/temp/review_seed_manifest.jsonl`. Running the same command again skips
hotels whose latest manifest status is `index_verified` and resumes the
remaining hotels.

Use `--no-resume` to rebuild selected hotels even if their manifest entries are
already verified:

```bash
uv run scripts/seed_review_summary.py --apply --limit 5 --no-resume
```

Use `--manifest PATH` to keep or resume from a different manifest. Available
controls also include `--min-reviews`, `--max-reviews`, `--concurrency` (1-4),
and `--retries`.

### Data replacement scope

For each selected hotel, the script performs these idempotent operations:

- Upserts deterministic reviews tagged with
  `seed_source=review-summary-dataset-v2-direct` and removes obsolete reviews
  previously generated by this seed version for that hotel.
- Replaces all points for that hotel in `review_summary_text_units` and
  `review_summary_entities`.
- Replaces that hotel's `Entity` node in Neo4j; relationships attached to the
  replaced node are removed, and this minimal index intentionally creates no
  `RELATES` relationships.

Do not run `--apply` against an environment whose existing review-summary
indexes must be preserved. A manifest records completed work, but it is not a
backup. If indexed data changes after a successful run, use `--no-resume` to
rebuild and verify the affected hotel range.
