### `trip-review-summary` 作为 MCP server 的业务接入建议

结论：推荐把 `trip-review-summary` 增加为 MCP server 供 `trip-chat-service` 的 agent 调用，同时保留现有 HTTP/A2A 能力。原因是评论总结更像一个结构化工具调用：输入是 `target_id`、`target_type`、`question`，输出是摘要、证据片段、索引状态；用 MCP 比让 chat 通过 A2A file part 传 `target_id` 更稳定，也更容易做权限、参数校验和可观测性。

建议 MCP 工具边界：

| MCP 工具                  | 业务职责                                                     | 完成度要求                                                   |
| ------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `query_review_summary`    | 根据 `target_id`、`target_type`、`question` 查询评论 GraphRAG，返回答案、引用的 text units/entities、索引更新时间和数据不足提示。 | 复用现有 `LocalSearch`，但必须补 `target_type` 入参并贯穿 Qdrant/Neo4j 查询 |
| `get_review_index_status` | 按 `task_id` 或 `target_id + target_type` 查询索引状态。     | 需要记录索引任务状态、更新时间、评论数量、失败原因           |
| `list_target_reviews`     | 可选底层工具，给 agent 或调试侧查看分页原始评论。            | 可直接代理 `trip-review-service`，但生产提示词里应优先用 summary/query 工具 |

接入顺序建议：

1. 先补 `trip-review-summary -> trip-review-service` 数据源：增加 review gRPC client 和 Nacos/env 地址解析，分页调用 `ListReviewsByEntity`，支持 `hotel` 和 `attraction` 两类目标。

2. 增加 text unit 同步任务：把每条评论转成 `TextUnit`，payload 带 `review_id`、`target_id`、`target_type`、`rating`、`dimensions`、`created_at`、`updated_at`，经 Higress/OpenAI embeddings 写入 `review_summary_text_units`。

3. 调整现有索引链：`collect_text_units` 不应假设 Qdrant 里已经有 text units；可以在它之前加 `sync_review_text_units`，或让 `collect_text_units` 负责缺失时从 review\-service 拉取。移除 `target_type != "attraction"` 的限制。

4. 补查询侧 `target_type`：A2A executor 目前只从 JSON file part 取 `target_id`，`LocalSearchMixedContext` 也默认按 attraction 查 text units；MCP 工具需要显式接收并传递 `target_type`。

5. 补业务化失败语义：没有评论、索引不存在、索引过期、Qdrant/Neo4j 无结果时，返回可解释的业务状态，不要让 agent 把技术异常当成“没有差评/没有问题”。

6. 在 `trip-chat-service` 接 MCP：当前 chat 已有 ADK `McpToolset`，但只接了 stdio weather server；weather-mcp是一个很小的包，直接在`trip-chat-service`里安装，不要独立开。

7. 在前端传目标上下文：酒店/景点详情页聊天时要把 `target_id`、`target_type` 放进 agent state 或工具上下文；酒店详情页的点评 tab 目前只是占位，酒店卡片点评数也写死为 0，需要接 `trip-review-service` 的列表/计数/评分。

8. 统一部署：root compose 已有 review\-service、review\-summary、worker、Redis、Qdrant、Neo4j；`deploy/docker-compose/docker-compose.yaml` 仍缺 review\-service/review\-summary/worker/Neo4j。确定后续样本用哪个 compose，并补健康检查与依赖条件；`trip-review-summary` app 本身也应显式依赖 Qdrant。
